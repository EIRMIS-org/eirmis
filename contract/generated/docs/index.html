Event Invitation and RSVP Management Information System (EIRMIS)

This contract is the single source of truth for every HTTP operation the React SPA may call against the Supabase backend (PostgREST + Edge Functions). It is authored and reviewed like code — a contract change requires approval from both the frontend and backend sides.

Two Backend Surfaces

  1. PostgREST data endpoints (/rest/v1/<table>) — curated read and simple-write operations the app is entitled to make. Authorization is RLS, not client-side discipline.
  2. Edge Function endpoints (/functions/v1/<name>) — anything that needs a secret, a privileged write, or a multi-step transaction.

What is NOT in this contract

  • Supabase Realtime — the attendance dashboard WebSocket channel is managed through supabase-js directly and documented in the README §9.
  • Supabase Storage signed-URL reads — gallery image and HTML invitation URLs are obtained via supabase-js Storage API, not HTTP operations.
  • Supabase Auth endpoints — magic-link, Google OAuth, and session management are handled by supabase-js Auth API.

Auth

All operations require a Supabase JWT (bearerAuth) unless explicitly overridden with security: []. The two genuinely public operations (open-registration event lookup and guest upsert) are the only ones that may opt out of authentication.

Error Model

A single Error schema — { code, message, details, hint } — matching PostgREST's native error shape. Edge Functions must return this exact shape and the same HTTP status codes so src/lib/api has exactly one error path.

PostgREST Query Parameter Conventions

PostgREST uses a specific query syntax. Key patterns:

  • Filtering: ?col=eq.value, ?col=in.(a,b), ?col=is.null
  • Column selection: ?select=col1,col2,related_table(col3)
  • Ordering: ?order=col.asc, ?order=col.desc
  • Pagination: ?limit=20&offset=0
  • Row count: send Prefer: count=exact header; result in Content-Range
  • Return body: send Prefer: return=representation on POST/PATCH
  • Upsert: send Prefer: resolution=merge-duplicates on POST with a conflict column

Organizer — Events

Event creation and management.

List events (organizer-owned or public discovery)

Dual-mode endpoint — behaviour depends on whether a bearer token is supplied.

Authenticated (organizer): Returns the caller's own non-deleted events. RLS restricts the result set to organizer_id = auth.uid(). All status values are visible. Use ?status=eq.published or ?status=in.(draft,published) to narrow by lifecycle state.

Unauthenticated (public discovery): No bearer token required. The caller MUST supply both ?visibility_mode=eq.open_registration and ?status=eq.published to satisfy the RLS anon-read policy, which only exposes open-registration published events to unauthenticated requests. This is the query used by the /register/:slug public registration flow to resolve an event before rendering the sign-up form.

In both modes, soft-deleted events (deleted_at IS NOT NULL) are hidden by RLS and do not appear in results.

Dual-mode endpoint — behaviour depends on whether a bearer token is supplied.

Authenticated (organizer): Returns the caller's own non-deleted events. RLS restricts the result set to organizer_id = auth.uid(). All status values are visible. Use ?status=eq.published or ?status=in.(draft,published) to narrow by lifecycle state.
